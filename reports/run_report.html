Leak Ledger — run report

Reconciliation and leakage detection over a 3-source synthetic batch with published ground truth. Every figure below is produced by the metrics harness.

Across 542 payments and 41 bank rows, Leak Ledger confirmed Rs 474517.27 of leakage — 2 chargeback not recredited, 3 duplicate capture, 2 duplicate payout, 11 fee overcharge, 6 gst mismatch — every instance verified against ground truth. It flagged a further Rs 1060629.55 across MISSING_SETTLEMENT, RESERVE_NOT_RELEASED, which are not confirmed: those detectors report instances ground truth does not support, so that value is a claim pending review, not a finding. It refused to match 22 records, each with a stated cause.

Gross of both: Rs 1535146.82. The split matters — 69% of the gross figure comes from classes whose measured precision is below 1.00, and quoting the gross alone would overstate confidence in exactly the way this build argues against.

3 · Findings

What “value claimed” means. It sums every instance the engine reported, not just the ones ground truth confirms — because that is what the tool actually claims when it runs. A deployed engine has no ground truth and cannot filter its own output down to the instances that happen to be right; reporting only verified value would flatter the tool using knowledge it does not possess at run time. The of which verified column is therefore shown beside it, and any class with FP > 0 is excluded from the confirmed headline above.

5 · AI judgment

where a model is usedwhat constrains it
Bank narration → candidate entitiesProposes only. Accepted only if the named reference exists and the amount agrees exactly. Confidence is never consulted.
Exception rationaleDiscarded if it introduces a figure absent from the evidence; the deterministic string is shown instead.
Settlement Q&ARead-only. No write path exists — enforced by the function signature, not by convention.
Verified with an adversarial provider that returns confidently wrong, well-formed answers: every metric above is identical with it wired in, and false-match rate stays at 0.0000. A boundary that depends on the model behaving is not a boundary.
Stated gap — the LLM-as-matcher benchmark has not been run.
No live model credentials were available at build time. The record selection is frozen and committed (harness/benchmark_selection.json) so it provably predates any result, and harness/benchmark_llm_matcher.py refuses to run without credentials and writes nothing. Self-disagreement, accuracy, latency and cost are therefore unmeasured and unreported rather than estimated.
